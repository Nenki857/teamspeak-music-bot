# 公开发布说明

## 仓库与成品

GitHub 仓库保存项目源码、必要资源、部署脚本与说明；EXE、ZIP、服务器部署压缩包放到 Releases，不提交到 Git。项目自身代码采用根目录 LICENSE 中的 MIT 许可证，第三方组件保留各自许可。

这次整理没有修改正在运行的机器人，也没有更新已经生成的 EXE/ZIP。现有 Windows 包捆绑的 GPL FFmpeg 尚缺完整对应源码的提供安排。需要根据实际二进制补齐源码、外部库与构建资料等分发要求，或调整成品的分发方式后，再公开上传 Windows 成品。仓库中的版本号、许可证文本或源代码链接不能单独解决这个问题。

服务器源码包不附带 Node、FFmpeg、SinusBot 或 TS 客户端可执行文件；相关组件在部署端单独获取。各组件仍适用其自身许可。详见根目录 THIRD-PARTY-NOTICES.txt 和 resources/licenses/。

## 个人信息与历史提交

当前源码中的个人服务器地址已换成示例地址或用户输入，电脑专属的脚本路径已改成通用路径。实际连接设置继续保存在被忽略的 work/deployment/settings.json。

普通提交只能修改当前版本，不能清除旧提交。此前提交中的服务器地址和作者邮箱仍可能通过历史记录看到。本次没有改写历史、强制推送或修改 GitHub 仓库可见性。

若这些历史信息不希望公开，可以从这份干净的项目源码目录创建全新仓库；这里没有 .git，因此不会携带旧提交。另一种做法是备份后专门清理现有仓库历史，需要重新核对分支、标签和远程记录。不要只删除当前文件就认为历史信息消失了。

之后的提交可在 GitHub 的 Settings → Emails 中启用邮箱隐私，复制 GitHub 显示的 noreply 邮箱，再用于 GitHub Desktop 的 Git 作者设置。这个设置不会改变旧提交。

## GitHub Desktop 提交

1. 在应用整理结果后，打开 GitHub Desktop 的更改列表，查看本次修改。
2. 确认列表中没有账号、Cookie、数据库、SSH 私钥、日志、运行目录或安装包。
3. 摘要可写：整理公开源码，补充 MIT 许可并移除个人部署信息。
4. 提交后点 Push origin（推送到远程）。本次整理工具不代为提交、推送或改变公有/私有设置。
5. 如需隐藏旧历史中的邮箱和地址，先完成历史处理，再把原仓库改为公有。

.gitignore 只防止未跟踪文件被正常加入；已被 Git 跟踪的敏感文件不会因此自动消失。源代码中的测试假数据也不应替换成真实登录信息。

## 保留的数据

账号、网易云登录状态、歌单、TS 身份、部署密钥和运行目录不属于公开源码。整理应用程序只替换清单里的项目文件，并先备份被替换文件；不会覆盖 .git、server-data、data 或现有连接配置。
