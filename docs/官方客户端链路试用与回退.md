# Ubuntu 官方 TS3 客户端链路试用

本次只增加服务器版的可选链路，Windows 本地版继续使用原实现。原实现没有删除，默认仍为 `TSMD_AUDIO_BACKEND=custom`。新实现为 `official`，使用第三方 SinusBot 1.0.2 音频桥及其兼容的官方 TeamSpeak 3 Client 3.5.6；SinusBot 不是 TeamSpeak 官方音乐机器人。现成插件不兼容 TS3 3.6.x 的插件 API，不能只把下载版本改成 3.6.2；此组合用于在自己的 TS3 服务器上做链路对照，不能称为“最新版官方客户端方案”。若坚持较新客户端，需要另行编写匹配其插件 API 的音频桥。独立 TeamSpeak SDK 不能直接代替普通 TS3 客户端连接普通 TS3 服务器，因此没有采用独立 SDK 路线。

## 先保存当前队列

切换会重启音乐后台，正在播放的内存队列不会自动续播。请先在主人页面保存需要保留的队列。已保存歌单、简介、账号、预设和固定邀请继续使用现有服务器数据，不需要重新搬迁。

## 存档位置

- 本机完整源代码存档：`archives/TS-Music-Desk-original-chain-2026-10-18T12-40-28-682Z.tar.gz`，SHA-256 为 `15454b5e80eb52b2fe2ea76fd6712633b6995d8e06227e3fdf905d55609a19fa`。包含 852 个源代码、测试、界面、内核及锁文件，不含账号、数据库、密钥、node_modules 和运行时二进制。逐文件摘要在包内 `AUDIO-CHAIN-ARCHIVE.json`。
- 切换入口先在真正运行的服务器上再创建一次存档，保存于安装目录的 `runtime/audio-chain-archive-*`。程序源码压缩包和 SHA-256、原 server.env、SQLite 一致性备份及密钥均留在服务器，目录权限 700；不会上传到聊天或复制进发行包。最新路径记录在 `runtime/last-audio-chain-archive.path`。

源码存档可用于重建旧版本；锁文件及原有运行环境需要保留。数据快照是紧急恢复手段，不用于日常切换，以免覆盖切换后新增的歌单。

## 试用

双击工程目录的 `切换服务器官方链路.cmd`。它严格校验已确认的主机指纹，然后依次：

入口会先在本机准备官方 Linux 组件，再进行以下服务器步骤。优先读取工程 `release/server/tools/sinusbot.current.tar.bz2` 或本机默认 `Downloads/sinusbot.current.tar.bz2`，否则尝试从官方文档给出的 `https://www.sinusbot.com/dl/sinusbot.current.tar.bz2` 下载。若自动下载报 HTTP 403，先在自己的浏览器打开 [SinusBot 官网](https://www.sinusbot.com/)，选择 **Download for Linux 64 bit**，保留原压缩包和默认文件名，不解压，然后重新运行切换工具。官网要求网页验证时由用户自行处理；脚本不会绕过验证，也不使用不明镜像。只有准备成功才更新、重启音乐后台。

准备程序检查完整压缩格式和所需文件，然后经 SSH 上传，服务器核对 SHA256 后使用该文件，避免服务器再次下载。此 SHA256 是传输完整性校验，不是厂商签名认证；安装包来源应保持为官网下载。已安装的 SinusBot 和 TS 客户端继续复用。真实官网发行包尚未在当前工具环境下载成功，HTTP 403 的人工下载步骤仍需在用户浏览器完成。

1. 在服务器存档现有程序和私有数据。
2. 使用小更新包部署可切换的程序，仍先保持原链路。
3. 安装 Xvfb、SinusBot 和官方 TS3 客户端；只绑定音频桥 API 到 `127.0.0.1:18087`。无需新增公网端口，不改变已有 TS 服务或固定 HTTPS 入口。
4. 在你的 SSH 终端展示官方客户端许可，由你阅读并决定是否接受。脚本不会代替你输入接受操作。
5. 启用独立的 `ts-music-desk-official.service`，验证私有 API 登录和实例，将凭据使用现有服务器密钥加密保存到 `server-data/official-transport.json`，随后切换后台环境并检查主人网页就绪。

首次需要下载第三方音频桥、官方客户端和图形依赖，可能较慢；以后回退不重新下载。需要现有免密 sudo 安装权限。上游下载或安装失败时不会写入 official 音频选项。环境切换后的启动检查失败会恢复切换前的选项。

完成后刷新主人网页，默认预设的自动连接规则不变；如果没有自动连接，在控制台启动机器人。新客户端使用独立身份，服务器的频道准入或发言权限可能需要重新分配。登录与好友权限仍由 Music Desk 管理，朋友无需登录 SinusBot。

## 实际播放流程与功能

Music Desk 查询网易云、管理队列及权限 → 将当前曲的临时播放地址发送给本机私有音频桥 → SinusBot 解码和缓冲 → 音频桥插件注入官方 TS3 客户端 → 官方客户端处理编码及 TS3 语音传输 → TS 服务器 → 听众客户端。

音乐数据不再经过原 Node 音频播放器的 20ms 定时器、原生 Opus 模块或自实现 TS3 UDP 发送器。搜索、歌单和网页的 JSON 处理与音频服务分属不同进程。原队列算法仍保留：插播保留列表，被打断歌曲从头排在下一位；进度、音量、播放模式、自建歌单、开放歌单、频道链接分发继续通过原界面操作。

SinusBot 采用保存位置、停止、重新播放并 seek 来实现这里的暂停续播，恢复可能重新缓冲；不是保持原网络流的无缝暂停。私有桥初次取流 45 秒仍未开始时会报告错误，保留队列供重试。频道列表仍不读取，优先使用预设中的频道 ID；频道名称必须唯一，复杂路径请填写频道 ID。资源面板把独立音频服务及官方客户端的进程家族计入 CPU / 内存。

“播放链路诊断”会明确标记官方客户端模式，不再展示原内核帧计数作为音频正常的证据。工具未采集听众实际收到的音频，不承诺仅换链路就消除所有失真。请用同一首歌、相同频道和近似听感音量比较，留意不操作及搜索时是否都有改善。

## 一键回退

双击 `恢复服务器原链路.cmd`。它停止音乐后台和官方客户端服务，将唯一的音频选项改为 `custom`，移除官方服务依赖后重启后台。保留当前账号、歌单、预设、固定 HTTPS 及持久邀请设置；不自动恢复旧数据库快照，不覆盖后来新增的资料。原内核文件、身份和依赖没有移除。

阶段记录在本机 `work/audio-transport-last.log`。服务器可检查：

如果安装窗口已经关闭，可双击工程目录的 `检查服务器音频链路.cmd`。此入口通过原 SSH 主机指纹校验，上传只读检查助手，读取组件存在状态、当前音频选项、两个音乐服务的退出状态，以及初始化日志 / 服务日志里可识别的错误类别。它不安装依赖、不更新程序、不修改环境、不重启或控制播放。不会输出原始日志、密码或账号文件内容。报告写入本机 `work/audio-transport-report.txt`，检查阶段另记 `work/audio-transport-check-last.log`，原安装失败日志保持不变。未识别的日志不会原文输出，因此可能仍需进一步定向检查。

```bash
systemctl status ts-music-desk-official --no-pager
journalctl -u ts-music-desk-official -n 40 --no-pager
```

官方客户端身份与第三方音频桥自身数据还保存在 `runtime/sinusbot/data`；今后备份该模式时，应连同其 config.ini 和现有 server-data 保存，不能只备份 Music Desk 数据库。

初始化日志 `server-data/sinusbot-init.log` 可能包含第三方音频桥的初始密码，权限为 600，请勿分享该文件。当前版本是可试用的适配实现，真实 Linux 二进制、许可证交互、API 兼容性和实际频道听感须在目标服务器验证；本地合成测试不能代替这一步。

初始化重试保留首次密码记录，不覆盖旧日志；已有“Initialization complete”和密码记录时复用结果。初始化退出 255 只有在输出明确包含完成标记和初始密码记录时才能继续创建服务，其他失败仍中止；之后还必须通过私有 API 登录验证才能选择官方链路。安装阶段再次失败时，Windows 入口自动运行只读检查并保存报告，窗口关闭后仍可排查。检查报告包含完成 / 密码记录的布尔标记，以及过滤凭据行、URL 和长标识后的少量错误摘要。
